# Code style
- Never write comments in source code or configuration code files. No inline comments, no block comments, no docstrings, no commented-out code.
- This applies to every language and file type (source, YAML, JSON, TOML, shell, Dockerfiles, etc.).
- If something needs explaining, explain it in your chat response, not in the file.
- When editing existing files, do not add new comments; leave existing ones alone unless clearly outdated, unnecessary, or wrong.
